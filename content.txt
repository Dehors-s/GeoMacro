## 关键发现与解决

### 1. ArcGIS Pro XML vs Desktop 10.8 XML 差异

| 特性 | Desktop 10.8 | ArcGIS Pro 3.0 |
|------|-------------|----------------|
| 日期格式 | `Tue Apr 21 14:22:13 2026` | `2026年4月25日 16:49:11` |
| 参数格式 | 纯 Parameters | Parameters + Environments + Messages + LayerInfo |
| 文件完整性 | 完整 | 偶有截断（缺 `</ResultViews>`） |
| ToolSource 路径 | `d:\arcgis\desktop10.8\...` | `d:\arcgis pro 3.0\...` |

### 2. 中文环境适配

- **参数名全中文**（如 `输入要素` → 无法用作 arcpy 关键字名）
- 解决方案：自动降级为**位置参数**（`arcpy.analysis.Clip(working, FIXED_CLIP, out_clip)`）
- 英文参数名保留关键字形式（`in_features=working`）

### 3. In-place 工具处理

工具如 `CalculateField`、`RepairGeometry` 的输出与输入是同一文件。
- 自动检测 `input_path == output_path`
- 生成 `_copy_features_for_inplace()` 保护原始数据
- 输出参数从 arcpy 调用中剔除（该工具不接受）

### 4. CodeTaskFactory 与 dotnet build 不兼容

ArcGIS Pro SDK 的 `Esri.ProApp.SDK.Desktop.targets` 使用 `CodeTaskFactory`（.NET Framework MSBuild 专用），与 `dotnet build`（.NET Core MSBuild）不兼容。
- 解决方案：`dotnet build /p:DisableArcGISPackaging=true` 编译 DLL，然后手动打包成 `.esriAddinX` 并通过 `RegisterAddIn.exe` 安装
- 已编写自动化脚本：`scripts/dev/build-addin.ps1`

### 5. .esriAddinX 结构（Pro 3.x 要求）

```
GeoMacroAddin.esriAddinX
├── Config.daml             ← 插件清单（必须放在根目录）
└── Install/
    └── GeoMacroAddin.dll   ← 编译后的 DLL（必须在 Install/ 子目录）
```

## 已知限制（Phase 2 待改进）

1. 🟡 **工具白名单有限** — 目前仅 12 个工具。需用户在 `template_registry.py` 中手动扩展
2. 🟡 **无通用反射方案** — 未实现从 arcpy 工具签名自动推断参数结构
3. 🟡 **面板目前不可交互编辑参数** — 变量名和参数值不能在 Pro 面板中直接编辑
4. 🟡 **仅支持线性流水线** — 不支持分支/循环/条件逻辑
5. 🟡 **没有 Dry-run** — 验证会检查语法但不执行试运行
